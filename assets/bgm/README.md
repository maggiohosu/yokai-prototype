# 요괴 키우기 (yokai-game) 배경음악 (BGM) 라이브러리

동양 설화풍(산해경·선협) 귀여운 요괴 성장 게임의 분위기를 살린 적응형 배경음악(BGM) 4종입니다.
외부 음원이나 상용 샘플 라이브러리를 일절 사용하지 않고, Python DSP(numpy, scipy) 물리 모델링 및 가산/FM 합성 알고리즘을 통해 **100% 코드로 자작 합성**되었습니다.

---

## 1. 배포 음원

네 곡 모두 D 평조 5음계(D·E·G·A·B), 4/4박자, 44.1 kHz 스테레오다. Antigravity의 악보와 합성 음색으로 각 곡을 48초씩 렌더링했다. 80 BPM의 두 마디와 120 BPM의 세 마디는 모두 6초다. 게임은 필드 곡을 전환할 때 같은 재생 위치에서 새 곡을 시작한다.

통합 음량과 트루 피크는 배포 파일을 FFmpeg `ebur128=peak=true`로 해독해 측정했다. 한 칸에 두 값이 있으면 OGG(Vorbis), MP3(LAME) 순서다. kB는 1,000바이트다.

| 곡 | 사용 장면과 악기 | BPM | 길이 | 크기 OGG / MP3 (kB) | 통합 음량 (LUFS) | 트루 피크 (dBTP) |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| calm | 여유로운 탐색과 먹기. 가야금과 대금, 가벼운 장구 | 80 | 48초·16마디 | 378.42 / 384.57 | −16.8 / −17.2 | −5.2 / −5.7 |
| tense | 큰 적 접근·굶주림·피격. 빠른 북과 짧은 피리 구절 | 120 | 48초·24마디 | 408.95 / 384.57 | −17.2 / −17.6 | −5.7 / −6.0 |
| boss | 대요괴가 살아 있는 동안. 대북과 징, 편종 | 120 | 48초·24마디 | 403.63 / 384.57 | −18.5 / −18.9 | −5.7 / −6.1 |
| title | 타이틀·도감·결과. 풍경·편종과 가야금 | 80 | 48초·16마디 | 364.48 / 384.57 | −16.8 / −17.2 | −6.1 / −6.1 |

형식별 총량은 OGG 1,555,477바이트, MP3 1,538,260바이트다. 브라우저는 곡마다 재생 가능한 형식 하나를 받아 해독하며, 실패하면 다음 형식을 시도한다. 음악 기본값 0.5는 음악 버스 게인 0.25(−12.0 dB)로 적용한다. 선택지·정비 중에는 여기서 8 dB 더 줄인다.

## 2. 합성 기법 및 사운드 디자인

모든 음원은 `assets/bgm/generate_bgm.py` 파이썬 스크립트에서 직접 합성되었습니다.

1. **가야금 / 고쟁 (Gayageum)**:
   - 오동나무 울림통 공명(260Hz, 540Hz)과 탄현 손톱 노이즈 과도응답 모델링
   - 고차 배음일수록 빠르게 감쇠하는 물리적 지수 감쇠($\tau_k = \tau_0 / k^{1.15}$)
   - 지속음 0.25초 이후 자연스럽게 걸리는 한국 전통 농현(비브라토) 알고리즘
2. **대금 / 디즈 (Daegeum)**:
   - 가로 대나무 피리의 취구 숨소리 노이즈 변조
   - 갈대 청(淸)의 비선형 포화 버징($y = \tanh(1.8x) + 0.1x^2$)을 통한 특유의 찌르르한 동양 피리 음색
   - 온셋 추성/퇴성(미세 피치 슬라이드) 및 4.8Hz 감성적 비브라토
3. **편종 / 풍경 (Bianzhong / Wind Chime)**:
   - 청동 제례악기 고유의 비정수 배음 모드(`[1.0, 2.76, 5.40, 8.90, 13.30]`) 모달 가산 합성
   - 투명하고 맑은 고주파 반짝임과 긴 여운 잔향
4. **소리북 / 대북 / 장구 / 징 (Buk, Janggu, Jing)**:
   - 소리북: 125Hz에서 54Hz로 지수 강하하는 막 진동 피치 스윕과 나무 틀 타격 틱
   - 대북: 95Hz에서 42Hz로 떨어지는 강력한 저역 서브 펀치
   - 장구: 저음 가죽 궁편(Gungpyeon)과 날카로운 대나무 채편(Chaepyeon) 타격음
   - 징: 135Hz 기본음에 215Hz FM 변조 및 3.2Hz 맥놀이 울림

### 반복 경계 검증

52초를 렌더링해 48초 경계를 넘어간 잔향 4초를 앞에 더하고, 정확히 2,116,800 프레임을 출력한다. 아래 값은 최대 진폭을 1로 둔 샘플 단위다. 경계값은 마지막 샘플과 첫 샘플의 절대 차이 중 좌우 채널의 최댓값, p99는 같은 곡 안의 인접 샘플 절대 차이의 99백분위다.

| 곡 | 원본 PCM 경계 / p99 | OGG 경계 / p99 | MP3 경계 / p99 |
| --- | ---: | ---: | ---: |
| calm | 0.00939 / 0.06391 | 0.00920 / 0.05963 | 0.02275 / 0.05190 |
| tense | 0.00157 / 0.06587 | 0.02928 / 0.06222 | 0.01027 / 0.05460 |
| boss | 0.00224 / 0.06016 | 0.00688 / 0.05672 | 0.00188 / 0.04866 |
| title | 0.00653 / 0.06786 | 0.01097 / 0.06356 | 0.00936 / 0.05506 |

Chrome의 `OfflineAudioContext`로 여덟 파일을 44.1 / 48 kHz에서 각각 해독했다. 모두 정확히 48초(2,116,800 / 2,304,000 프레임)였고, `AudioBufferSourceNode`로 반복 경계를 가로질러 렌더링한 앞뒤 16샘플씩에서 양 채널 모두 신호가 이어졌다. Chrome은 MP3 인코더 패딩을 제거했다. iOS Safari 실기기 재생은 별도 확인 항목이다.

### 재생 쪽 처리 (`src/audio/bgm.js`)

- **반복 길이 표**: `generate_bgm.py`의 `LOOP_SEC`, `bgm.js`의 `LOOP_SEC`, 위 표의 길이는 같은 값(네 곡 모두 48초)이다. `tests/bgm.test.mjs`가 세 곳을 대조하고, 생성 스크립트는 렌더한 프레임 수가 이 값과 다르면 중단한다. 재생할 때는 `loopStart = 0`, `loopEnd = LOOP_SEC`를 함께 지정한다. 브라우저가 MP3 인코더의 앞뒤 지연을 남겨 두어도 곡 길이에서 되감는다.
- **클릭 방지**: 탭 숨김·세로 화면·음소거·`destroy`는 소리를 60 ms 램프로 내린 뒤 80 ms에 정지한다. 음량 변경도 50 ms 램프로 옮긴다.
- **메모리**: 해독된 PCM은 곡당 약 17 MB(48초·44.1 kHz·스테레오·32비트 실수)다. 판이 시작될 때 `calm`·`tense`·`boss`만 남기고 `title` 해독본은 버린다. 압축 파일(곡당 약 0.4 MB)은 계속 들고 있어 다시 받지 않고 그대로 다시 해독한다. `boss`는 압축 파일만 미리 받고 처음 나올 때 해독한다.

## 3. 재현 및 빌드 명령어

```bash
# 전체 BGM 4종 음원 재생성 및 OGG/MP3 인코딩
python assets/bgm/generate_bgm.py
```
*(요구 환경: Python 3.x, numpy, scipy, ffmpeg)*
