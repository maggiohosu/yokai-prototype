너는 이 저장소의 구현 담당이다. 계획·검수는 Claude Opus가 한다. 먼저 docs/spec.md(기획), docs/plan.md(설계), docs/research.md(부품 설계)를 모두 읽어라.

이번 작업: **1단계만** 구현한다 — 이동, 4색 요괴 먹기, 크기 판정, 적 AI, 카메라 줌아웃. 2단계 이후 기능(발사·진화·강화·저장)은 만들지 말고, 넣을 자리만 구조로 남겨라.

## 기술 조건
- 빌드 없는 정적 사이트. index.html + src/ 아래 ES 모듈. Phaser 3.90.0을 https://cdn.jsdelivr.net/npm/phaser@3.90.0/dist/phaser.min.js 에서 <script>로 불러온다(전역 Phaser).
- GitHub Pages 하위 경로에서도 돌아가도록 모든 경로는 상대 경로.
- 세로 화면 기준. Phaser.Scale.RESIZE, 화면 크기가 바뀌면 UI 재배치. 터치 스크롤·확대 막기(touch-action:none, user-scalable=no). 고해상도 화면에서 흐리지 않게.
- 모든 수치는 src/config.js 한 곳에 (맵 크기, 구역별 색 비율, 적 수, 적 크기 분포, 속도, 성장량, 먹기 판정 비율, AI 감지 거리, 줌 공식 등).

## 구현 내용
1. 맵: 넓은 정사각 맵(예 4000x4000), 동·서·남·북 4구역. 구역마다 해당 방위 색 요괴가 60% 이상(config). 바닥은 구역별 은은한 색 + 점/격자 무늬로 이동감이 보이게. 맵 경계 표시.
2. 플레이어: 1단계 '미물'. 크기(size)=체력=반지름 기준값. 왼쪽 화면 아무 곳이나 누르고 끌면 그 자리에 생기는 플로팅 조이스틱. 끌기 방향·세기로 이동. 데스크톱 테스트용 WASD/방향키도.
3. 요괴(적): 4색(동·청, 서·백, 남·적, 북·흑). 크기는 플레이어보다 작은 것이 많고 큰 것도 섞임. 형태는 src/data/forms.js의 2·3단계 중 방위가 맞는 것을 크기에 따라(작으면 2단계, 크면 3단계).
4. 먹기: 겹치면 크기가 일정 비율(config, 예 1.1배) 이상 큰 쪽이 작은 쪽을 먹음. 먹은 쪽은 면적 합산 기반으로 커짐(config 계수). 플레이어가 먹히면 '판 종료' 화면(먹은 수·최대 크기·다시 하기 버튼).
5. 적 AI 3규칙: 감지 거리 안에서 플레이어보다 작으면 도망, 크면 추격, 그 외 배회. 적끼리도 단순하게 먹을 수 있게. 적 수가 줄면 화면 밖에서 다시 생성.
6. 카메라: 플레이어 추적. 커질수록 부드럽게 줌아웃(config 공식, 최소 줌 제한).
7. 화면 위쪽에 현재 크기, 먹은 수 표시.
8. 캐릭터 그래픽(중요): src/data/forms.js에 17종 데이터(id, name, stage, dir, branch(yo/seon/none), parts[], desc 한 줄)를 docs/research.md 기준으로 모두 작성. src/art/creature.js에 부품 함수(몸통, 큰 눈+흰 하이라이트, 볼터치, 굵은 외곽선, 귀 종류, 꼬리 n개, 뿔, 사슴뿔, 등껍질, 날개, 외다리, 여섯 다리, 더듬이, 등의 눈, 흰 머리, 불꽃, 상투, 도포 깃, 물방울 몸, 방망이, 연기 테두리 등)를 만들고 Phaser Graphics → generateTexture로 형태별 텍스처를 한 번만 구워 캐시. 선 갈래는 흰 기운 테두리, 요 갈래는 붉은 눈빛. 등급 테두리 함수 자리도 만들어 둠(3단계에서 사용). 귀엽고 통통하게, 밝은 색. 기존 캐릭터와 닮지 않게.
   - 확인용: index.html?gallery=1 로 열면 17종을 격자로 보여주는 도감 화면.
9. 성능: 휴대폰 60fps 목표. 적 60~80마리.
