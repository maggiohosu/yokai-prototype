# 사방 들판 UI 디자인 감사

- **제품** 휴대폰에서 미물을 움직여 요괴를 먹고 다음 모습으로 키우는 게임.
- **성격** 들판에서는 재빠르게, 도감과 성장 선택에서는 차분하게.
- **재료** 크림색 종이 위의 짙은 녹색 먹선. 방위 색은 지도와 요괴 표본에 쓴다.
- **주인공** 들판의 요괴와 새 모습이 처음 도감에 오르는 순간.
- **서명** 들판에는 방위 한자, 판을 마치면 끝을 뜻하는 終, 새 모습을 얻으면 등급을 작은 인장처럼 찍는다.

## 수정 전 관찰

기준은 `2ffbbf5`의 원본 행 번호다. Chrome에서 360×780 CSS 픽셀로 여덟 장면을 촬영했다. 기본 들판에서 발사 구슬의 광택과 화면 끝에서 끊긴 조작 안내가 눈에 먼저 들어왔다. 정비에서는 활성 탭, 각 강화 버튼과 다음 판 버튼이 모두 같은 무게로 보였다. 진화를 마치면 회전하는 광선이 새 요괴의 몸보다 넓었다. 기존 종이색, 먹색 머리글, 방위 구분, 캐릭터의 굵은 외곽선에서 방향을 잡았다.

### 적용 범위

히어로, 첫 화면 80단어, 1280×800의 히어로 행동 버튼, 1920px 랜딩 컨테이너는 해당 없음. 플레이의 기준은 360×780이며, 모달에서는 바닥 동작을 화면에 두고 목록만 스크롤한다. 핵심 순간인 **‘성장할 때!’**는 행동 중 화면이 멈춘 이유를 한눈에 알려 주므로 유지한다. 기존 요괴 그림과 방위·등급·확률은 게임의 실제 자료다. 도감이 생성하는 ‘동녘 · 청’과 HUD의 단계·등급은 서로 다른 분류 값을 잇는 표기다. 두 생성기는 이번 작업의 수정 범위 밖이다.

## 아홉 패스의 적용 결과

| 순서 | 패스 | 화면에서 확인할 변화 |
|---|---|---|
| 1 | 간격 | 들판의 모서리 여백은 12px, 모달과 도감 가장자리는 16px가 기준이다. 확률·비용·동작 사이에는 8px, 다른 강화 항목 사이에는 16px와 구분선을 두었다. |
| 2 | 색 | 색과 한글 글꼴을 `src/style.css`의 `:root`에서 관리한다. 미니맵의 방위 색도 HUD 생성 때 한 번 읽는다. 먹색은 행동과 제목, 인주색은 終 인장과 발견 기록에 쓴다. |
| 3 | 아이콘 | 장식 별·불필요한 화살표를 지우고 발사 버튼과 장착 장비에 같은 납작한 여의주 표식을 썼다. 도감 링크에는 이름을 항상 보인다. |
| 4 | 문구 | ‘들판을 누른 쪽으로 이동’이 360px에서 한 줄에 들어간다. 보상은 사망 사유 다음 줄에, 속도·파워 등은 각각 이름 옆에 표시한다. |
| 5 | 글꼴 | 명조는 이름과 제목, 고딕은 설명·비용·확률에 쓴다. 도감 설명을 11px에서 14px로 올리고 수치 폭을 맞췄다. |
| 6 | 배치 | 정비는 한 줄에 한 능력, 진화는 그림 아래 이름, 도감은 두 열을 유지한다. 결과에서는 사유를 읽고 한 줄 아래에서 보상을 확인할 수 있다. |
| 7 | 세부 | 누르는 조작에는 44px 이상의 높이와 즉시 나타나는 키보드 초점선을 적용했다. 결과를 네이티브 대화상자로 열어 배경 포커스를 막고 재시작 또는 정비로 넘어갈 때 닫는다. |
| 8 | 시각 | 그림 뒤 점무늬·빛살·색 후광을 걷고 등급은 글자가 있는 인장으로 바꿨다. 발사 바깥 고리의 두 색은 실제 재충전량을 가리킨다. 터치 조작의 지름은 72px, 넓은 화면의 정밀 포인터용은 52px다. |
| 9 | 모션 | 미지 후보의 반복 광택과 회전을 없앴다. 일반 모드에서는 결과에 180ms 농도 변화만 주고, 모션 감소 설정에서는 진화 그림과 역전 알림을 정지 상태로 보여 준다. |

## 화면 비교

비교본은 로컬 Chrome의 360×780, 배율 1, 한국어 환경에서 촬영했다. 전후 모두 같은 시작 상태를 사용했다. 병행 중인 캐릭터 확장의 영향을 분리하기 위해 수정 후 비교 촬영 때만 기존 커밋의 `creature.js`와 `forms.js`를 브라우저에 제공했다. 두 참조 파일의 버전 고정은 브라우저 응답에만 적용했다. 진화의 보조 후보와 배경에 등장하는 적은 게임 진행 시점에 따라 달라질 수 있다.

## 검증 및 인계

- **기존 테스트** `node --test "tests/*.test.mjs"` 93개 통과, 실패 0개. 작업 중 공유 폴더에 다른 확장 변경이 포함된 시점에는 98개 중 적 진화 테스트 한 건이 실패해 조정자에게 전달했다. 최종 93개는 디자인 작업의 기준 트리에 있는 전체 테스트다. 두 작업을 합칠 때 확장 테스트도 다시 실행한다.
- **문법과 도구** 수정한 JS 5개의 `node --check`와 `git diff --check` 통과. Hallmark sloplint는 원본 HTML/CSS 세 파일 정적 검사에서 FAIL 154, REFLEX 88, WARN 7을 냈다. 최종 세 파일과 들판·정비·진화·도감 네 URL에서 렌더 검사를 실행해 FAIL 0, REFLEX 0, WARN 0을 확인했다. 원본 숫자는 리터럴·속성별 중복을 포함하며, 감사 표의 27개는 원인별 묶음이다.
- **실제 조작** 발사 후 충전, 결과창에서 Tab으로 정비 선택, 다음 판 재시작, 강화 지불·결과, 여의주 확률 펼침, 진화 선택·확인, 몸집 강화 후 재개를 점검했다. 도감 필터는 표시 중인 고유 형태 수와 종수가 일치했다.
- **접근성** 320·360·390px에서 가로 넘침과 모달 하단 버튼 위치를 확인했다. 모션 감소 상태에서 진화 그림과 역전 문구가 움직이지 않았고 JavaScript를 껐을 때도 활성화 안내가 보였다.
- **후속 제안** 캐릭터 확장 통합 후 가장 긴 형태명과 많은 후보가 들어간 진화 확률표를 320px 실기기에서 한 번 더 본다. 이번 비교의 도감은 원본 17종 기준이다.

감사에는 Damir Sokolovsky의 unslop(CC BY 4.0)과 Hallmark의 app/polish 기준을 사용했다.
